# 学童 給与予測 自動化 仕様書（Claude Code 引き継ぎ用）

## 背景・目的
放課後児童クラブ（学童）11ヶ所×2エリア（浜松/磐田）を運営。
毎月、①シフト予定 → ③各学童の給与明細Excel → ②全社集計Excel、という
3段階の転記・集計作業を、事務作業の負担軽減のため自動化したい。
今回はまず磐田エリア（11学童）を対象に検証。

## 毎月アップロードされるファイル（月ごとに内容が変わる）

1. **①シフト表（xlsx）**
   学童ごとにシートが分かれる（例:「向笠」「大藤」「岩田」「豊田北部①〜③」
   「豊田東①②」「豊岡南①②」「豊岡北」等）。
   - 4行目が見出し行（先生の名前 or 空欄 or 「非常勤」）
   - 5行目以降が1日1行（1ヶ月分、31行前後）
   - A列=日付, B列=曜日, C列=行事予定等, D列以降=各先生の勤務時間

2. **③各学童の給与明細シート（xlsx、学童ごとに個別ファイル、11ファイル＋短アルバイト期用1ファイル）**
   - シート構成: `★常勤` `☆非常勤` `一覧` `給与`（集計用） + 先生ごとの個人シート（複数）
   - 個人シートの13〜43行が1日ずつ（13行目=1日目）
   - **事務が中締め（16〜23日目安）まで実績を入力済みの状態で毎月渡される**
   - 続きの日数分を、①のシフト予定から埋めるのが今回の自動化のゴール

3. **②全社集計Excel（xlsm）**
   「磐田」/「浜松」シートに11学童分の行があり、E列(給与)/F列(処遇改善手当)/G列(交通費)に
   ③の合計額を転記する。**③→②の転記ロジックは確定済み（下記参照、`totals_to_summary.py`に実装・検証済み）**

## ③→②の集計転記ロジック（確定・検証済み）

③の「給与」シートは、先生ごとに約13〜14行の繰り返しブロックになっている
（各ブロックはB列に見出し「名前」が現れる行から始まる）。
1ファイル（＝1学童）分の全ブロックを合計して、事業所合計 aa/bb/cc を出す。

```
i = 8
while i <= 1000:
    if Cells(i,2) == "名前":
        i += 1
        a = Cells(i+6, 2)                       # 基本給
        b = Cells(i+8, 7)                        # 処遇改善
        c = Cells(i+10, 2) + Cells(i+10, 3)       # 非税通勤 + 課税通勤

        if Cells(i+5, 5) == "法定内残":            # ※正社員テンプレートのみこの項目が存在する
            a += Cells(i+6, 5)     # 法定内残
            a += Cells(i+6, 9)     # 業務手当
            a += Cells(i+8, 8)     # 残業手当
            a -= Cells(i+10, 6)    # 不労控除
            a += Cells(i+6, 11)    # 休業手当
            a = max(a, 0)

        aa += a   # → ②のE列（給与、処遇改善除く）
        bb += b   # → ②のF列（処遇改善手当）
        cc += c   # → ②のG列（交通費）
    i += 1
```

- **重要**: 「給与」シートは数式なので、計算済みの値を取得するには
  `openpyxl.load_workbook(path, data_only=True)` で開くこと（③ファイルが一度でも
  Excelで開いて保存されていれば、キャッシュされた計算結果が読める）
- 「法定内残」ラベルの有無で分岐が変わるのは、正社員用テンプレートと
  アルバイト等のテンプレートで項目数が違うため（この分岐だけで自動的に対応できる。
  事前に正社員/アルバイトを判定する必要はない）
- 豊岡北小のデータで実行し、給与773,360円・交通費26,829円という現実的な値が出ることを確認済み

②側への書き込み:
```
ii = 73
while Cells(ii, 1) != "":
    if Cells(ii, 4) == 学童名:
        Cells(ii, 5) = aa
        Cells(ii, 6) = bb
        Cells(ii, 7) = cc
    ii += 1
```
- 「磐田」シートは73行目から、「浜松」シートは別の開始行がある可能性があるので要確認

## ③への書き込みルール（個人シート、日付の行）

| 列 | 項目 | 内容 |
|---|---|---|
| C列 | 出勤時間 | 時刻（例 13:00） |
| E列 | 退勤時間 | 時刻（例 18:30） |
| T列 | 特記 | 時刻の代わりに「有休」「欠勤」「休出」「慶弔」「休業」等のキーワード。この場合C・E列は空欄 |
| K列 | 休憩(分) | **給与予測目的のため60分固定でOK**（勤務時間が6時間を超える日のみ。6時間以下は0/空欄という運用を仮定。要検証） |

## 正社員・アルバイトの判定（仮ルール、要ユーザー確認が完了していない）
- ①の列見出しに名前がある列のうち、先頭（D・E列など）が正社員、それ以外はアルバイト・非常勤という配置が多い
- 「有給」「欠勤」の表記がある場合は正社員、それ以外の記載や空欄はアルバイトの可能性が高い、との事業者側の説明あり（**まだ最終確認は取れていない、要再確認**）

## 名前 → ③ファイルの紐付けルール

1. 全ての③ファイル（11学童＋短アルバイト期）を走査し、`{先生名: (ファイル名, シート名)}` のインデックスを作る
   - 除外シート: `★常勤` `☆非常勤` `一覧` `給与` `未入力*`
   - シート名先頭の `◎` は名前の一部ではないので除去して比較する
2. **同じ名前のシートが複数ファイルに存在するケースがある**（実際に10件確認済み）
   → シートタブの背景色が **赤（RGB: FFFF0000）** の方は「使っていない（無効な）シート」。
     赤タブは名前インデックスから除外する。
3. 応援・アルバイトの先生の勤務時間は、**実際に働いた学童のファイルではなく、
   その人の名前のシートがある③ファイル（本来所属している学童 or 短アルバイト期ファイル）に
   まとめて記録する**（ユーザー確認済み）

## ①シフト表の読み取りルール（かなり表記ゆれが多いので要注意）

### セルの値のパターン分類
1. **時刻レンジ**: `7:30-16:30` 等。区切り文字は `-` `〜` `～`（全角/半角）、
   コロンは `:` `：`（全角/半角）が混在する。正規表現は表記ゆれ全部に対応させること。
2. **学童名のみ**（例:「豊岡南1」「岩田小」「向笠」）:
   その先生は他の学童に応援に行った日。**該当する学童の①シートを見に行き、
   同じ日・同じ人の実際の時刻を探す**（クロスリファレンスが必要）
3. **名前＋行き先＋時刻が1セルに混在**（例:「芥川8:00～13:00」「豊岡北8:00～13:00」）:
   セル内に埋め込まれた名前と時刻を正規表現で抽出する
4. **分割シフト（1日2回勤務）が改行で1セルに入っている**
   （例:「鍵屋7:30～11:00\n15:30～18:00」）:
   改行で分割して複数の時間帯として扱う必要がある
5. **休み・特殊表記**: 「休」「×」「x」「有休」「欠勤」「お盆休み」等 →
   ③のT列に該当キーワードを書き込む（有休・欠勤等）か、その日は何も書かない（休・×等、要確認）
6. **見出しが空欄の列でも、日付行に時刻や名前が入っていることがある**
   → 見出し行に名前がある列だけでなく、**全列を走査**する必要がある

### 各学童シート共通の「イベント日」
土曜日などに「AM豊田東②、PM豊岡南①」のような全学童共通のイベント注記が
C列（行事予定等）に入ることがある。これは個人の勤務時間ではなく、
学童全体の予定メモなので、パースの対象外（先生ごとの勤務セルとは別）。

## まだ確認・検証が済んでいないこと（次にやるべきこと）
1. ~~②への転記（給与/処遇改善手当/交通費の内訳）の正確なセル対応~~ → **解決済み（上記参照）**
2. 正社員/アルバイト判定ルールの最終確認（※③→②の転記では判定不要と判明。
   ①→③の書き込み時の休憩(K列)ルール等ではまだ関係する可能性あり）
3. 「休」「×」の日にT列に何も書かないという理解で合っているか
4. 分割シフト・混在セルのパースを実装 → 複数月のデータで精度検証
5. K列（休憩）の「6時間超で60分」ルールの検証（実データでの当てはまりを再確認）
6. 「浜松」シートの書き込み開始行（②のiiの初期値。「磐田」は73行目からと判明済み）
7. 本番運用前に、事務の方が最終チェックする一覧（誰の・どの日を・どう解釈して埋めたか）
   を出力するようにし、いきなり③・②に書き込むのではなく確認フローを挟む設計にすることを推奨

## 実装（プロトタイプ → `kyuyo` パッケージ）

引き継ぎ資料の `shift_to_kintai.py` / `totals_to_summary.py` を出発点に、
①→③→② の全工程を `kyuyo/` として実装した（使い方は README.md）。

| 資料のプロトタイプ | 実装先 |
|---|---|
| `shift_to_kintai.py`（①読み取り・名前インデックスのドライラン） | `kyuyo/shift.py` `kyuyo/kintai_index.py` `kyuyo/plan.py` `kyuyo/kintai_write.py` |
| `totals_to_summary.py`（③→②の集計転記） | `kyuyo/totals.py` |

追加したもの: 表記ゆれの正規化（`kyuyo/textutil.py`）、応援先のクロスリファレンス、
分割シフト、赤タブ除外、確認用レポート（`kyuyo/report.py`）、ダミーExcelでの自動テスト。

## 実装時の判断メモ（要ユーザー確認）

実データが無い状態で決めた仮ルール。実データで検証して、違っていればここを直す。

1. **休憩(K列)**: 勤務時間（出勤〜退勤の合計）が6時間を**超える**日のみ60分。6時間ちょうどは0分。
2. **分割シフト**: ③は1日1行なので、C列＝最初の出勤・E列＝最後の退勤とし、
   間の空き時間を休憩(K列)に加算する（例: 7:30〜11:00＋15:30〜18:00 → C=7:30 E=18:00 K=270分）。
   1.の60分は、この空き時間とは別に、勤務時間が6時間超なら加算する。
3. **「休」「×」等**: ③には何も書かない（T列にも書かない）。
   「有休」「欠勤」「休出」「慶弔」「休業」のみT列に書く（「有給」は「有休」に寄せる）。
4. **上書き**: 既にC/E/T列のどれかに値がある日は「事務が入力済み」とみなして上書きしない
   （`--overwrite-filled` で変更可）。
5. **氏名の照合**: 完全一致 → 部分一致（候補が1件のときのみ）。複数候補は自動で決めず要確認に回す。
6. **列見出しの先生と違う名前がセルに書かれている場合**: 見出しの先生として扱ったうえで警告を出す
   （どちらの勤務か自動では決めない）。
7. **時刻のコロン省略**: 3〜4桁は下2桁を分として解釈（`1800`→18:00、`830`→8:30）、
   1〜2桁は「時」のみ（`13-18`→13:00-18:00）。
8. **②の走査開始行**: 「磐田」73行目。「浜松」は未確認のため暫定で同じ73行目
   （`--start-row` で指定可能）。

### 未解決（1. 〜 7. は元の「まだ確認・検証が済んでいないこと」に対応）

- 休憩ルール・「休」「×」の扱い・②浜松の開始行 → 実データで確認が必要
- 正社員/アルバイト判定: ③→②では不要と判明。①→③でも現状は判定していない
  （休憩ルールを雇用形態で分ける必要があるなら要追加）
- ①のセルが「要確認」に落ちるパターンは毎月レポートに出るので、
  出現したものを SPEC.md に追記しながらパターンを育てる
