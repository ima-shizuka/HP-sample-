# 学童 給与予測 自動計算

放課後児童クラブ（磐田エリア11学童）の毎月の転記作業を自動化するツール。

```
①シフト表(xlsx)  ──plan/apply──▶  ③各学童の給与明細シート(xlsx)  ──summary──▶  ②全社集計(xlsm)
   学童ごとのシート                個人シートのC/E/K/T列を埋める        E/F/G列に事業所合計
```

業務ルールの唯一の情報源は [SPEC.md](SPEC.md)。ズレを見つけたら SPEC.md に追記してから実装を直す。

> **給与に関わるデータです。** `plan` で出したレポートを事務の方が目視確認してから
> `apply` する運用にしてください。既定では原本を書き換えず、`out/` にコピーを作って書き込みます。

## いちばん簡単な使い方（Windows・「開始」をダブルクリック）

1. `input` フォルダに今月のファイルを置く
   - ①シフト表 → `input\shift.xlsx`
   - ②全社集計 → `input\summary.xlsm`
   - ③給与明細シート → `input\kintai\` の中に全部（**ファイル名はそのまま**。学童名の判定に使います）
2. **`開始.bat` をダブルクリック**
3. 画面の質問に答えるだけ

```
【1/3】①を読んで一覧を作る        → out\plan.csv が自動で開く → 目視確認
    ↓「この内容で書き込みますか？」に y
【2/3】③に書き込む                → out\kintai\ にコピーができる
    ↓ ③をExcelで開いて保存（数式の再計算のため）→ y
【3/3】②に集計を転記              → out\summary.xlsm ができあがり
```

`input` フォルダやファイルが足りないときは、何が足りないかを表示してフォルダを開きます。
初回は openpyxl の自動インストールが走ります（Python本体は別途インストールが必要）。

`n` と答えればその場で終了し、③②は書き換わりません。原本は常にそのままで、
結果は `out` フォルダに作られます。

### 完全自動化（プロンプトなし）

毎月同じ設定で実行する場合、対話プロンプトをすべて飛ばすことができます：

1. **`config.example.json` を `config.json` にコピー**
   ```bash
   cp config.example.json config.json
   ```

2. **`config.json` を編集**
   ```json
   {
     "from_day": 13,        // 中締めの翌日（例：12日中締めなら 13）
     "area": "磐田",        // ②のシート名（磐田 / 浜松）
     ...（他の設定）
   }
   ```

3. **`開始.bat` をダブルクリック**
   - `config.json` が自動で読み込まれ、プロンプトなしに実行される
   - ③の書き込み後、**Python が自動で Excel を開いて数式を再計算**（手動作業なし！）
   - ②への転記も自動実行
   - すべて完了するまで待つだけ

> **注意：** 毎月、`config.json` の `from_day` を更新してから`開始.bat` を実行してください。
> 更新忘れすると前月の日付で埋まります。

## セットアップ（コマンドで使う場合）

```bash
cd salary_prediction
pip install -r requirements.txt      # openpyxl と pywin32（③の自動再計算用）
```

### Windows 環境での注意

- **開始.bat で実行する場合**: 初回に pywin32 が自動インストールされます（追加設定不要）
- **pywin32 について**: Windows の COM インターフェースを使って Python から Excel を自動操作し、
  ③ファイルの数式を自動で再計算します。Excel がインストールされていれば動作します。

## 使い方（毎月の流れ・コマンド版）

```bash
# 0) ③の氏名インデックスを点検（同名シート・赤タブの確認）
python -m kyuyo index --kintai-dir input/kintai

# 1) ①を読んで「誰の・どの日を・どう埋めるか」をレポート出力（まだ書き込まない）
python -m kyuyo plan --shift "input/①.xlsx" --kintai-dir input/kintai --from-day 24
#    → out/plan.md（要確認リスト付き）と out/plan.csv が出る

# 2) レポートを確認したら③に書き込む（out/kintai/ にコピーを作って書き込み）
python -m kyuyo apply --shift "input/①.xlsx" --kintai-dir input/kintai --from-day 24 --yes

# 3) 書き込んだ③を Excel で開いて保存し直す（数式の再計算のため。後述）

# 4) ③の合計を②へ転記
python -m kyuyo summary --kintai-dir out/kintai --summary "input/②.xlsm" --area 磐田 --write
```

毎回同じ引数を打たなくて済むように、`config.example.json` をコピーして
`--config config.json` で渡せます（CLIで指定した値が優先）。

> **重要：** `開始.bat` を使う場合は、`config.json` が自動で読み込まれます。
> wizard モードでプロンプトを完全に飛ばしたい場合は、`config.json` に `from_day` と `area` を設定してください。

### 主なオプション

| オプション | 意味 |
|---|---|
| `--from-day` / `--to-day` | 埋める日の範囲。中締め（16〜23日目安）の翌日を `--from-day` に指定する |
| `--sheets 向笠 大藤` | ①の対象シート（学童）を絞る。既定は全シート |
| `--in-place` | ③の原本を直接書き換える（既定は `out/kintai/` にコピー） |
| `--overwrite-filled` | 事務が入力済みのセルも上書きする（既定は上書きしない） |
| `--area 磐田` / `--start-row` | ②のシートと走査開始行（磐田=73行目） |

## 何を自動で判断しているか

### ①シフト表の読み取り（`kyuyo/shift.py`）

| セルの例 | 解釈 |
|---|---|
| `7:30-16:30` `8:00～13:00` `８：００〜１７：００` `13:00-1800` | 勤務時間（区切り・コロンの全角/半角、コロン省略に対応） |
| `7:30〜11:00`＋改行＋`15:30〜18:00` | 分割シフト（1日2回勤務） |
| `豊岡南1` のように学童名だけ | 応援。その学童の①シートの同じ日・同じ人の時刻を引く（クロスリファレンス） |
| `芥川8:00～13:00` `青島凛さん13:00-1800` | セル内の氏名＋時刻を抽出（見出しが空欄/「非常勤」の列） |
| `有休` `欠勤` `休出` `慶弔` `休業` | ③のT列にキーワードを書き、C/E列は空にする |
| `休` `×` `お盆休み` 等 | ③には何も書かない |
| 上記以外 | 「要確認」としてレポートに出す（自動では書き込まない） |

- 見出し（4行目）が空欄の列にも勤務が書かれていることがあるため、**D列以降の全列**を走査する
- C列の行事予定（`AM豊田東2、PM豊岡南1` 等）は学童全体のメモなので対象外
- 応援・アルバイトの先生の勤務は、応援先ではなく**本人のシートがある③ファイル**にまとめる

### 固定シフトの先生（`fixed_shifts.json`）

①シフト表に出てこない先生や、毎月同じ勤務の先生は `fixed_shifts.json` に書いておくと自動で埋まります
（`fixed_shifts.example.json` をコピーして使ってください）。

```json
{
  "rules": [
    { "person": "山田花子", "file": "【統括】", "weekdays": "平日",
      "time": "9:30-18:30", "break_minutes": 60, "note": "土日祝休み" },
    { "person": "佐藤一郎", "file": "【豊田東小第1】", "weekdays": "土", "time": "13:00-18:00" }
  ],
  "extra_holidays": ["2026-08-13", "2026-08-14"]
}
```

| 項目 | 意味 |
|---|---|
| `person` | 氏名（③のシート名の表記に合わせる） |
| `file` | 書き込み先の③ファイル名の一部。同姓同名がいる場合や、①に出てこない先生に指定する |
| `weekdays` | `平日` / `土` / `土日` / `月-金` / `["月","水"]` |
| `time` | `9:30-18:30` のような勤務時間 |
| `break_minutes` | 休憩(分)。省略すると通常ルール（勤務6時間超で60分） |
| `exclude_holidays` | `true`（既定）なら祝日は出勤しない。祝日は**自動計算**（振替休日・国民の休日も含む） |
| `extra_holidays` | お盆休みなど、祝日以外の休業日を日付で指定 |

- **①に記載がある日は①が優先**されます（実際の予定が入っているため）。優先した旨はレポートに出ます。
- 対象の年月は①のA列の日付から自動判定します（日付が無い場合のみ `--year 2026 --month 8`）。

### ③への書き込み（`kyuyo/plan.py`, `kyuyo/kintai_write.py`）

- 行: 13行目＝1日目（`row = 12 + 日`）
- C列＝出勤、E列＝退勤、K列＝休憩(分)、T列＝特記
- 休憩(K列)は「勤務時間が6時間を超える日は60分」（給与予測目的の仮ルール）
- 分割シフトは C列＝最初の出勤・E列＝最後の退勤 とし、**間の空き時間を休憩に加算**する
  （例: 7:30〜11:00＋15:30〜18:00 → C=7:30, E=18:00, K=270分 → 実働6時間）
- 既に値が入っている日（＝事務が中締めまでに入力済み）は上書きしない

### ③→②の集計（`kyuyo/totals.py`）

元のExcel VBAをそのまま移植（SPEC.md の確定ロジック）。「給与」シートの
「名前」ブロックを合計して、②のD列が学童名と一致する行のE/F/G列に書き込む。

## 📊 数式の再計算について

③の「給与」シートは数式なので、openpyxl は**Excelがキャッシュした計算結果**を読みます。
`apply` で③を書き換えると、このキャッシュが消えます。

### 自動化（開始.bat 使用時）
wizard モードでは、**Python が pywin32 を使って自動で③を Excel で開いて保存**します。
ユーザーが手動で保存する手間は不要です。

### 手動実行時の注意
コマンドラインから実行する場合は、以下の順に実行してください：

**`apply` → ③をExcelで開いて保存 → `summary`**

キャッシュが無い状態で `summary` を実行した場合は、
`Excelで一度開いて保存し直してください` というエラーを出して、0円で集計してしまうのを防ぎます。

## よくあるエラー

| メッセージ | 対処 |
|---|---|
| `①シフト表が見つかりません` | `salary_prediction` フォルダにいるか（`dir` で `kyuyo` が見えるか）、`input\` にファイルを置いたかを確認。メッセージに「同じフォルダにあるExcel」が出るので、名前の綴りを見比べる |
| `③のフォルダが見つかりません` | `mkdir input\kintai` で作り、③を全部入れる |
| `①シフト表を開けません` | 古い `.xls` 形式の可能性。Excelで開いて `.xlsx` で保存し直す |
| `Excelで一度開いて保存し直してください` | ③をExcelで開いて保存してから `summary` を実行（数式の再計算のため）<br/>※ 開始.bat なら自動実行されるため不要 |
| `python が見つかりません` | Python未インストール、またはインストール後にターミナルを開き直していない |

## ファイル構成

```
salary_prediction/
├── SPEC.md              業務ルール・データ構造の仕様書（最重要）
├── 開始.bat             ダブルクリックで対話モードを起動（Windows）
├── config.example.json  毎月の実行設定のひな形
├── kyuyo/
│   ├── textutil.py      表記ゆれの正規化・時刻/キーワード/学童名の解釈
│   ├── shift.py         ①の読み取り＋応援先クロスリファレンス
│   ├── kintai_index.py  ③の氏名インデックス（赤タブ除外・同名検出）
│   ├── plan.py          書き込み計画（行・列・休憩の算出）
│   ├── kintai_write.py  ③への書き込み（コピー先に出力・入力済みは温存）
│   ├── totals.py        ③→②の集計転記（VBA移植）
│   ├── report.py        確認用レポート（Markdown / CSV）
│   ├── wizard.py        「開始」から呼ばれる対話モード
│   └── cli.py           コマンドライン
└── tests/               ダミーExcelを生成して通しで検証
```

`kyuyo/shift.py` は引き継ぎ資料の `shift_to_kintai.py`、`kyuyo/totals.py` は
`totals_to_summary.py` を出発点にしています。

3. ②「浜松」シートの書き込み開始行（磐田＝73行目）
